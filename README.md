# FORM Studio — сайт студии танцев и аренды залов

Демо-концепт сайта для студии **FORM** на Петроградской стороне (Санкт-Петербург).
Четыре зала, два сценария — занятия и аренда, один календарь с онлайн-бронированием.

> ⚠️ Это вымышленный бренд. Демо-проект для портфолио.

---

## Что внутри

- **Главная** — hero, два сценария (занятия / аренда), четыре зала, живое расписание на сегодня, преподаватели, отзывы.
- **Занятия** — каталог направлений (High Heels, Strip Plastic, Стретчинг) с ценами, уровнями и преподавателями.
- **Аренда** — календарь «время × зал» с онлайн-бронированием в 2 клика. Свободные слоты подсвечены золотом, занятые — серые. После брони слот мгновенно становится занятым.
- **Расписание** — та же сетка, но объединяет занятия и аренду в одном окне.
- **Контакты** — адрес, телефон, форма вопроса с отправкой в Unisender.

### Ключевые решения

| Задача | Решение |
|---|---|
| Быстрое бронирование | Supabase + Server Actions + `revalidatePath` — слот обновляется мгновенно |
| Защита от двойной брони | `UPDATE … WHERE status='available'` (атомарный «claim») |
| Все слоты в одном календаре | `time_slots` с полями `room_id`, `date`, `start_time`, `type`, `status` |
| Уведомления | Unisender Go (транзакционные письма) — работает в РФ, оплата рублями |
| Дизайн | Тёмная тема + приглушённое золото (`#C6A96B`), скругления, шрифты Unbounded + Inter |

## Быстрый старт

### 1. Клонирование и установка

```bash
git clone <repo-url> form-studio
cd form-studio
npm install
```

### 2. Создание проекта в Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com), создайте новый проект.
2. Откройте **SQL Editor** и последовательно выполните:
   - содержимое `supabase/schema.sql` — создаёт таблицы `rooms`, `time_slots`, `bookings` и включает RLS;
   - содержимое `supabase/seed.sql` — наполняет 4 зала и генерирует расписание на 14 дней вперёд.
3. В разделе **Project Settings → API** скопируйте:
   - `Project URL`;
   - `anon public` — публичный ключ (можно отдавать в браузер, RLS разрешает только чтение);
   - `service_role` — секретный ключ (⚠️ только для сервера, никогда не коммитить).

### 3. Ключ Unisender Go (опционально)

1. Зарегистрируйтесь на [unisender.com](https://www.unisender.com/) и подключите **Unisender Go**.
2. Подтвердите домен отправителя и получите API-ключ в разделе интеграций.
3. Если ключ не задан — приложение продолжит работать, письма будут логироваться в консоль сервера.

### 4. Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните:

```bash
cp .env.example .env.local
```

```dotenv
# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
SUPABASE_SERVICE_ROLE_KEY=eyJ...

# Unisender Go
UNISENDER_API_KEY=xxxxx
UNISENDER_FROM_EMAIL=noreply@form-studio.ru
UNISENDER_FROM_NAME=FORM

# Студия
STUDIO_EMAIL=hello@form-studio.ru
```

### 5. Запуск

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Продакшен-сборка локально:

```bash
npm run build
npm run start
```

## Демо-сценарий (для портфолио)

1. Открыть **/rent** — в календаре видно 4 зала, свободные слоты золотые, занятые — серые.
2. Кликнуть на свободный слот — открывается модалка с формой (имя, телефон, email).
3. Заполнить и нажать «Забронировать».
4. Слот мгновенно становится серым, страница перерисовывается через `revalidatePath` + `router.refresh()`. На почту приходит подтверждение (если настроен Unisender).
5. Открыть **/schedule** — та же логика, но видны и занятия, и аренда одновременно.
6. На главной блок «Сегодня в студии» показывает актуальные слоты дня (тоже живой, обновляется после брони).

## Развёртывание на Vercel

1. Запушьте репозиторий в GitHub.
2. Откройте [vercel.com/new](https://vercel.com/new), импортируйте репозиторий.
3. **Environment Variables** — добавьте все ключи из `.env.local` (кроме `NEXT_PUBLIC_*` секреты тоже нужны как env-переменные проекта).
4. **Deploy**. Первая сборка — 1–2 минуты. Домен вида `*.vercel.app` открывается из РФ.

Для реального клиента в РФ лучше рассмотреть российский хостинг (Яндекс Облако, Selectel) — на Vercel иногда бывают проблемы с доступностью.

## Как устроена защита от двойной брони

В `app/actions/booking.ts`:

```ts
const { data: claimed } = await supabase
  .from('time_slots')
  .update({ status: 'booked' })
  .eq('id', slotId)
  .eq('status', 'available')   // ← атомарная проверка
  .select('id')
  .maybeSingle();

if (!claimed) {
  return { ok: false, error: 'Этот слот только что заняли. Выберите другое время.' };
}
```

Если два клиента одновременно жмут «Забронировать» на один слот — БД обновит строку только один раз, второй получит `claimed = null` и увидит ошибку. Это надёжнее, чем проверка в JS перед UPDATE.

## Ограничения демо и следующие шаги

Для демо специально **не реализовано** (описано как план развития):

- **Аутентификация и личный кабинет** — сейчас клиент бронирует без логина. В проде: magic-link через Supabase Auth, страница «Мои брони» с отменой.
- **Админка** — редактирование слотов, отмена броней, ручное подтверждение, рассылки. В проде: `/admin` с RLS по ролям.
- **Онлайн-оплата** — сейчас «оплата на месте или по ссылке». В проде: ЮKassa / Tinkoff Kassa с вебхуком и подтверждением брони только после оплаты.
- **iCal / Google Calendar** — экспорт расписания для арендаторов.
- **Антиспам** — reCAPTCHA или rate-limit на Server Action через Upstash / Vercel KV.
- **Тесты** — Playwright e2e на сценарий «клик → бронь → слот исчез».
- **Аналитика** — Vercel Analytics + цели на клики по кнопкам бронирования.
